# 约好的关心

主人明确说到自己的未来安排时，普通聊天可以记录一次有来源的关心计划。例如早上说
“今天出门，晚上才回家”，她可以在晚上问“到家了吗”。面试、考试等安排也可记录。
识别、记录、改期和关闭由原有聊天模型的工具调用完成，不另加一轮后台分类模型。
这里只关心事情进展，不代替闹钟，也不保证模型每次都能识别自然语言安排。

聊天工具先查询 `care_plan_list`，再用 `schedule_care` 记录或更新，事情结束或取消时用
`close_care` 关闭。日期使用 `current_time` 的时区；只说晚上回家时默认当地19点，模糊到
无法确定哪天时不记录。模型只能引用当前主人消息里的原文；转述、假设、故事、过去的事
不创建计划。更新必须带原计划版本。原消息、每次修改的消息及工具操作都有来源关联。

到期后使用原有 Life selector 的本地维护轮次，创建一个 `activity` 任务，由现有 worker
生成措辞，再经原有 Outbox 发送。消息直接对主人说话，用“你”，按意思空行分成一到三段。
发送到最近使用的主人私聊渠道，支持 QQ 和原生客户端。关心使用已有 `proactive` 授权；
不依赖 Life 自主授权或阅读任务授权，也没有额外发送通道。

记录时固定一个小幅随机偏移，重启不重新抽取。默认最多偏移10分钟，有效窗口为2小时，
且不跨到当地次日。错过窗口不补问；到期落在免打扰时段直接跳过。主人近期在聊天、
尚有待回复的输入、主动消息暂停、来源失效或权限失效时不发送。原话已说到家、结束、取消
时，聊天工具关闭计划；到期措辞仍可根据获准读取的近况选择 `[SKIP]`。

排队、模型调用、提交和投递都重新检查来源、时间、权限及当前近况。新消息到来后，旧措辞
不能继续投递。删除或撤回原消息及相关修改消息，会经原有擦除重放清空计划内容、作废旧任务。
“删除这条记忆（记忆有误）”只删除记忆，保留的原消息仍可支持关心计划。
已经送达的记录保留原证据；投递结果不确定仍保持 `DELIVERY_UNCERTAIN`。

控制台配置中的“约好的关心”对应：

```toml
[care]
enabled = true
daily_limit = 2
jitter_seconds = 600
useful_seconds = 7200
recent_chat_seconds = 600
```

还需 `proactive_enabled = true` 及现有主人主动消息授权。`daily_limit` 是每天独立的关心尝试
上限，不占主动分享次数；一项任务的多个气泡只算一次。取消、跳过、擦除或结果不确定不退还
已占用的当天尝试，避免反复生成。金钱预算仍使用原来的 `activity` 计费与未知费用处理。
最多保留16条待关心计划，计划时间不超过30天，并且不得超过原消息的有效保留期限。
单计划最多31个安排版本，另保留关闭所需的来源空间；超过时可关闭旧计划，从新消息记录。
近期历史读取服从现有 `history` 用途、起始时间、轮数和字节限额；没有历史授权则不读取近况正文。
`care` 配置沿用需重启生效的配置流程，控制台会显示待重启。

数据库升级为 `pg0010_care_plans`。旧库升级新增空表，不从历史消息批量补建计划；
离线 SQLite 导入也保留空表。回滚沿用完整备份恢复流程。
