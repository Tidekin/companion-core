# 牢记：重要记忆越过原始消息保留期（设计稿）

状态：主人已于 2026-11-16 确认（见“主人的决定”），按文末切片实现。

## 目标

人会牢牢记住随口提到的一些事，比如生日，但记不住原话的每个字。本设计让她自己判断哪些记忆
值得牢记。原始消息到期时，只留下支撑这条记忆的那一两句原话，其余部分照常删除。牢记的事
不会被忘掉：刚记下时常常想起，时间久了进入“不常回忆、但一提就想起来”的状态。

## 现状

- 原始消息按 `raw_event_retention_days`（默认 365 天）到期。`Runtime.expire_raw_events`
  每批最多处理 1000 条，写入 `raw_retention` 遗忘记录，然后清空消息正文
  （`ErasureLedger.apply`）。
- 记忆失去最后一条有效来源后，`expire_memory_evidence` 会把它降为待审查、置信度归零，
  不再参与检索。记忆正文仍保留在库里，但已经用不上。
- 主人授权模式下，每条主人输入都绑定主人签发的 `OwnerGrantPolicy.source_retention_days`
  （[owner_authority_protocol.py](../../companion/owner_authority_protocol.py)），
  `owner_input` 读取来源时会再按这个期限检查一次（[owner_input.py](../../companion/owner_input.py) 第 107、186 行）。
- 记忆提取时，模型会给每条候选打 1–10 分的 `salience`，算出的 `memories.importance`
  只用于排序。主人提及次数记在 `memory_mentions`（[召回鲜明度](../memory-salience.md)）。

## 约束

1. **不越过主人的授权。** 主人签的来源期限就是这条来源能用多久。牢记必须由授权明确允许，
   并且有单独的期限和数量上限；主人撤回授权后，下一次到期处理就让牢记照常过期。
2. **出处不变。** 牢记的出处仍然是主人本人的那条消息，只是正文缩短了。不另造“系统作者”的
   来源，不把她的判断当成事实证据。
3. **可重放。** 旧备份恢复后，必须重放到同样的结果：该裁剪的原话照样裁剪，该删的照样删。
   遗忘记录里不存正文，只存哈希。
4. **主人遗忘永远优先。** 主动遗忘、删除记忆和来源授权撤回，都按现有规则彻底清除牢记。
5. **只对记忆生效。** 日记、社交、目标、阅读等模块继续按原保留期把这条消息当作已过期，
   不读取裁剪后的原话。

## 设计

### 1. 授权：`keepsake` 策略

在 `OwnerGrantPolicy` 增加可选字段：

```text
keepsake: KeepsakePolicy | None = None
  retention_days: int | None # None（默认）= 一直保留，直到主人撤回授权或遗忘；也可设上限
  max_items: int             # 容量上限，默认 10000，只防失控，不作为日常淘汰手段
  max_excerpt_chars: int     # 每条节选的上限，默认 120，≤ 300
```

校验规则：设置 `keepsake` 时，`purposes` 必须包含 `memory`，并且 `memory_scope` 为
`owner_private`。不设置（默认）时，行为和现在完全一样。授权预览要用中文写明：
“她可以自己决定牢记一些重要的事；原消息到期后只保留相关的一两句原话，一直保留到你撤回或
让她忘记”。

### 2. 她怎么判断值得牢记

到期处理时，对每条即将失去最后有效来源的记忆打分。满足任一条件，即为候选：

| 条件 | 依据 |
| --- | --- |
| 提取时她给的 `salience` 平均 ≥ 9 | 现有 `memory_importance` 记录 |
| 主人在至少 3 个不同的日子提到过 | `memory_mentions` |

同时必须满足：

- 记忆主体是 `user`、`relationship` 或 `project`；
- 状态为 `CONFIRMED`，或者是没有冲突的 `HYPOTHESIS`；
- 不是敏感内容（复用 `memory_sensitive` 和凭据过滤）；
- 原消息来自主人私聊。

已经牢记的不会因为新的牢记被挤掉。只有“重复”可以替换：新候选和某条牢记是同一件事
（同一 `fact_key`，或新记忆 `supersedes` 旧记忆，例如生日改了），新的接替旧的，旧节选清空。
达到 `max_items` 时不再新增牢记，并在控制台提示主人；这个上限只是防失控的保险。

这一步只读已有数据，不调用模型。

### 3. 到期时裁剪原话

对选中的记忆，它最后一条来源消息不再清空正文，而是裁剪成一段节选：

- 按句号、问号、叹号、换行切句；
- 和记忆正文共享检索词最多的那 1–2 句，按原顺序拼接；
- 截到 `max_excerpt_chars`，保留原字。生日这类事通常只剩“人物＋日期”的一句，远短于上限；
- 新正文：`{"text": <节选>, "keepsake": {"memory_id": ..., "kept_at": ..., "excerpt_sha256": ...}}`。

同一批里的其他消息照常清空。裁剪是确定性的：同样的原文和记忆正文，一定得到同样的节选。

### 3.1 原文衍生内容（实现时补充）

被牢记的消息，对除记忆以外的一切都按已过期处理：对话摘要、经历、特质证据、回复内容、日记
投影以及其他派生清理照常执行。只保留记忆链路仍要用的几项：主人授权输入回执、授权来源、事件
日期（`memory-time`）、来源引用、重要度评分、主人提及和牢记记录本身。节选只支撑它被牢记的
那条记忆，同一消息对其他记忆的来源关联会被移除。

主人授权输入回执记的是原始正文的摘要。裁剪后正文里带着原摘要和节选哈希；只有 `memory`
用途、当前授权有 `keepsake`、牢记记录仍有效时，读取方才用原摘要核对回执，并按牢记期限代替
来源期限。其他用途照旧视为过期。

### 4. 遗忘记录与重放

`raw_retention` 记录新增 `keepsakes` 字段：
`[{"event_id", "memory_id", "excerpt_sha256", "until"}]`，其中 `until` 是消息到达时间加上
`retention_days`。记录里不存正文。

重放（恢复旧备份）时：

- 原文还在的，用原文和当时的记忆正文重算节选，哈希一致才保留，否则整条清空；
- 记忆已被遗忘或改写的，整条清空；
- 已过 `until` 的，整条清空。

结果只会删得更多，不会多留。

`until` 到期后，下一次到期处理会写一条普通的 `raw_retention` 记录，把这条节选也清空，
这条记忆随后照现有规则降级。

### 5. 哪些地方要认“牢记”

新增 `keepsakes` 表（`event_id` 主键、`memory_id`、`excerpt_sha256`、`until`（可空）、`kept_at`），
作为唯一的判断依据。下面这些检查对表里、未过 `until`、且当前授权仍允许牢记的消息放行：

| 位置 | 现在 | 改为 |
| --- | --- | --- |
| `Runtime.expire_raw_events` 选取到期消息 | `ingested_at < cutoff` | 跳过未过 `until` 的牢记消息 |
| `MemorySources._checked_lineage` 的期限判断 | `ingested_at < cutoff` 即失效 | 牢记消息按 `until` 判断 |
| `observation.expired_sources`（记忆调用处）、`recall_support`、`expire_memory_evidence` | 同上 | 同上，只在记忆路径放行 |
| `owner_input` 来源期限检查（`purpose="memory"`） | `min(授权期限, 保留期)` | 牢记消息改用 `keepsake.retention_days` |

其他模块不改，继续把这条消息视为已过期。

### 6. 她怎么说起

- 召回结果里，这条记忆带 `recollection: "approximate"`。回复的规则补一句：“这是很久以前的
  事，只记得大概，用‘我记得你好像说过……’这类语气，不要说成刚刚确认过”。
- 两种状态，按牢记后的时间和主人提及自动切换：

  | 状态 | 条件 | 怎么被想起 |
  | --- | --- | --- |
  | 常想起 | 牢记后一年内，或最近 90 天主人提到过 | 和普通记忆一样参与每次回复的自动召回 |
  | 有印象 | 其余 | 不进入每次回复的自动召回；主人的话原文命中它、或她主动调用 `memory_recall` 时才想起 |

  “有印象”的牢记不占自动召回的名额，所以数量多了也不会挤占日常记忆或拖慢回复，容量可以
  放得很大。主人再次提到时，它回到“常想起”。
- 排序：牢记本身不加额外分数，鲜明度照常按主人提及计算。

### 7. 控制台

- 记忆卡片显示“牢记”标签和当前状态（常想起／有印象）。详情显示节选。
- 每次新牢记一条，在活动时间线记一笔（只含记忆编号和原因代码，不含正文）。以后自研客户端
  有类似 QQ 空间的动态时，可以基于这条活动让她以第一人称发一条，例如“今天主人告诉了我他的
  生日，我要牢牢记下来”；那是另一项能力，不在本设计范围内。
- 新增操作“不用牢记”：从 `keepsakes` 移除，下一次到期处理照常清空。这个操作走现有的
  控制台幂等写入和审计。
- “忘记”行为不变：彻底清除，包括节选。

## 考虑过但不采用的方案

| 方案 | 不采用的原因 |
| --- | --- |
| 原始消息整条保留 | 留下的原话远超需要，违背“只记大概” |
| 固定小上限、按分数挤掉旧的 | 牢记的事被忘掉，违背本意；改为“有印象”状态扩容 |
| 新建一个系统作者的出处记录代替原消息 | 出处不再是主人本人，要改动所有来源校验，也会让“她的判断”变成证据 |
| 到期时让模型把记忆压缩成要点 | 要多一次模型调用和费用记录；节选已经是原话里的重要部分，先不做 |
| 不经授权，只靠配置开关 | 越过主人签的来源期限 |

## 主人的决定（2026-11-16）

1. 牢记的事不会被新的挤掉；只有重复的同一件事可以由新的替换旧的。
2. 不用每年几条的小上限。采用“常想起／有印象”两种状态，按需检索，容量放大。
3. 新牢记在控制台活动里记一笔；以后客户端有动态功能时再考虑让她发说说。
4. 节选上限先用 120 字，生日这类通常远短于上限。
5. “常想起”先按牢记后 1 年、主人提及后 90 天试行。
6. 默认一直保留（`retention_days = None`），只有撤回授权或主人遗忘才清除。

## 验证

- 到期：选中的记忆保持有效，节选和哈希一致，同批其他消息被清空。
- 不挤掉：新增牢记不改变已有牢记；同一事实的新记忆替换旧牢记；达到上限只停止新增。
- 两种状态：一年后转入“有印象”，不进入自动召回，但原文命中或工具召回仍能取到；主人
  再提到后回到“常想起”。
- 授权：没有 `keepsake` 时和现在完全一致；撤回后下一次到期全部清空。
- 重放：从更早的备份恢复，结果和原库一致或更少，不会更多。
- 遗忘：主人遗忘后，节选、牢记记录和提及都清空。
- 其他模块：日记、社交、目标读不到牢记消息。
