# 原生聊天的记忆预取与检索诊断

本片基于 `7683844`，复用 MemoryContext、FTS5/BGE/RRF、上下文规划与来源擦除。
用户确认范围是固定检索探针、可解释检索以及实体、时间线索评估。

## 发现与改动

原生 SDK 新会话把 `memories=[]` 交给 Core，初始请求没有自动检索结果。
即使问题能够命中记忆，模型也必须先主动调用工具才有机会看到它。
现在新会话按当前文本异步预取最多六个候选，继续由同一次回答判断相关性和冲突。
显式 `memory_recall` 工具仍然可用，并提示使用名称、编号、日期或有区分度的短语。

预取要求当前 owner/private 作业具有 memory 授权且记忆已启用。
空文本不预取；恢复会话沿用已保存的来源证明，不重复检索和模型请求。
推理前后重新验证授权、原始输入、隐私版本和证据；来源变更取消本次回复。
索引不可用沿用原错误处理，不能把它表述为没有历史记录。

预取和工具把诊断附在既有 memory 快照，包含查询哈希、候选数量及最终选中项的排名。
诊断不复制问题正文，也不保存被裁剪候选的身份；项目回顾兜底单独标记。
选中项继续绑定原来源闭包，来源擦除会清空对应会话与快照，原费用记录保留。
Console 既有 recall 接口同时返回相同搜索阶段的计数与排名，仍要求登录。

## 排序与探针的边界

本片保持编码器、语义门槛与 RRF 排序。
既有检索把未达到语义门槛的关键词候选也过滤掉；这会漏掉部分有效资料，
但直接放宽可能同时召回只共享通用措辞的无关事实。该问题由诊断与后续独立题库量化。
本次没有增加图谱、时间解析协议、媒体解析器或另一套存储。

`tests/fixtures/memory-recall-probes-v1.json` 固定 50 个本地检索问题，覆盖同名实体、
编号、日期、计划、转述、纠错、冲突、擦除、过期、越界与无记录。
这是已有事实的检索实验，转述文本也只是合成文本，不代表实际媒体解析能力。
固定样本召回 43 项必要事实中的 42 项；10 个无记录问题全部为空，额外候选 11 个，
已擦除、过期和公开范围的禁止来源泄漏为零。其余候选的相关性由回答模型判断。
这些样本已用于调试，不能作为盲测；没有以此宣称全量回答准确率提升。
