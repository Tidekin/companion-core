# 原图理解与纠正

原生聊天由 `agent_images.attach` 将有效原图附在当前或历史主人消息上；
统一图片规则按实际请求中的像素生效。事实、图内关系与寓意分别核对；
颜色和画风不能独自决定反转，也不能把图中角色自动对应为主人和助手。
事实或理解的纠正先处理具体分歧，再自然接话；普通照片不要求寻找反讽。
现有观察工具只记录文字、格序、人物、动作、重复与变化，不强制额外调用。

## 纠正资料

优先使用通过本地验证的 QQ 回复引用、原消息引用或明确来源 ID；
隐式目标最多查看已授权上下文中最近两条输入。多组图片有歧义时先确认目标，
不扫描全部聊天。既有历史范围、上下文预算、图片数量和 300 秒原图保存期保持生效。
当前图片优先，其次是正在核对的历史图片组，其余按新近程度选择；发送顺序仍按原历史顺序。

请求标明目标原图是否实际附入、未附入原因以及旧机器观察来源。
原图过期后的解释只能据旧记录或主人补充，不能声称重看。

在已有 memory 权限下，使用 `memory_references` 的可删除投影与来源 pin
追加 `image_review`：绑定具体图片组、已发送的旧解释、主人异议和当轮证据可见性。
原观察事件和发送收据不改写。异议、助手后来的改口、当轮有原图是三个不同事实；
它们均不自动证明更正正确。该记录不把模型自己声称“核实”升级成已核实事实。

历史回放在同一上下文块内带上有来源的异议和后续实际回复。
纠正不在已选择的历史范围内时，不额外读取其正文，并暂不重放有争议的旧解析。
从旧解析提取的记忆暂停作为确定依据，直到其引用不再处于有效争议中；
原收据仍保留。删除或撤回任一来源后，原有来源校验、Ledger 和投影清理使派生材料失效。

## 验证边界与参考

真实 HTTP 入口、独立 SDK worker、原图字节与顺序、使用结算、ACK、历史更正、
过期与删除检查只证明运行合同，不能证明模型理解了反讽。
语义评价必须使用隔离的裸图和固定纠正任务，单独衡量错误纠正导致的误改。

沿用现有输入和投影机制，没有新增依赖或第二个视觉服务。
参考 [DeepSeek 官方图像接口](https://api-docs.deepseek.com/zh-cn/guides/vision/)、
[DSH attachment](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/attachment)、
[MemeCap](https://aclanthology.org/2023.emnlp-main.89/) 对描述与寓意的区分，
以及 [HallusionBench](https://tianyi-lab.github.io/HallusionBench/) 的图文一致性评价。
这些材料支持诊断方法，不构成本项目提示有效性的实测结论。
