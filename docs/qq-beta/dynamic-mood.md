# 小肥鱼的动态心情

基线：2026-10-31 的 main `c7a13a6`，包含 Life 来源证据修订、聊天轮次与短回复上下文控制。
主人已确认采用确定性投影，先保证来源与连续性。
日常互动扩展基于 main `3a206d2`，继续复用原始私聊事件和已送达回复。
这是开发实现，默认 `mood_enabled = false`；部署时可在控制台配置页开启。Live 使用仍需
原有 `expression` 授权，阅读和目标还分别要求 `exploration`、`goals` 授权。

## 结构与复用

`affect.py` 继续只处理主人明确提出的交流偏好。`mood.py` 从同一 Core 数据库按需生成
`mood-2` 投影，不建立心情数据库、人格表、后台情绪任务或额外模型场景。

| 层 | 形成与消退 | 用途 |
| --- | --- | --- |
| 即时心情 | 真实事件的小幅变化；半衰期 3 小时，平滑趋近每维 ±0.35 | 近期表达参考 |
| 心情底色 | 至少三个独立来源后开始少量积累；半衰期 3 天，趋近每维 ±0.15 | 更缓慢的近期倾向 |
| 心绪手札 | 使用原有 Diary 的 reflection 段与 Reflection 暂时假设 | 回顾感受与原因，继续引用原始来源 |

PAD 依次表示愉悦度、唤醒度、支配感。表达参考为即时值加底色，每维绝对值小于 0.5。
数值是保守的产品规则，不是心理测量、固定人格或真实情绪体验的证明。0 也可以表示没有
足够依据；无来源时置信状态为 `unknown`，有来源时仍为 `limited`。

在相邻事件之间，按 `2 ** (-经过秒数 / 半衰期秒数)` 衰减。事件增量再乘以
`1 - abs(当前值) / 本层上限`，使变化有限且有惯性。底色只取即时增量的 12%。
这些权重、半衰期和上限均是本项目的首版参数，原始 PAD 研究没有验证这些聊天规则。
按原始时刻重放，不使用读取次数累计；跨日、重启、重算均得到相同结果。

## 哪些事件会产生变化

| 来源 | 必要证据 | 首版变化 P/A/D |
| --- | --- | --- |
| 明确帮助反馈 | 私聊主人原话，整句匹配；本会话已有实际 SENT 的回复，其原始输入仍有效 | 有帮助 +.08/+.02/+.02；感谢 +.06/+.01/+.02；明确没帮上忙 -.04/+.01/-.02 |
| 有趣的想法 | 对相邻已送达讨论的明确评价，如“这个想法挺有意思” | +.025 / +.02 / 0 |
| 继续探索的好奇 | 如“这个问题让我很好奇”“这个问题值得继续探讨” | +.01 / +.025 / 0 |
| 新角度带来的意外或惊喜 | 如“这个角度我真没想到”；明确“眼前一亮”才加愉悦度 | 0 / +.03 / 0；“眼前一亮” +.02 / +.03 / 0 |
| 观点分歧 | 如“这个观点我不认同”“我对这个观点有不同看法” | 0 / +.01 / 0 |
| 讨论进展 | 如“这样就说得通了”“我们把这个问题说清楚了” | +.025 / 0 / +.025 |
| Watch 评价 | 原生 JUDGED，原调用 SETTLED，正文或更深读取，真实 FETCHED/WATCHED 来源 | rating × .03 / 0 / 0 |
| 目标完成 | DONE 的最终来源、全部连续步骤及其真实观察回执与完整来源关联；没有 UNKNOWN | +.03 / 0 / +.04 |

明确词句范围见 `companion/mood.py::FEEDBACK` 与 `INTERACTIONS`。不从普通谢谢、随口寒暄、问句、引文、
生成回复、日记自述、沉默或回复间隔推导心情。首版不根据单次任务失败计算负面情绪。
没有充分证据时允许不更新。已取得内容不等于线下经历，模型自述不能单独生成来源。
若较新的回复尚在发送或投递结果不确定，后续反馈暂不采纳，不回退关联更早的已送达回复。

同一回复的多条反馈只采用最近一条；同一网址的同类阅读/目标只保留最近候选。
帮助反馈与日常评价共用同一回复身份，不能作为两次独立经历叠加。
一个观察同时有阅读评价和目标结果时合并为一次有界变化，每维增量不超过 0.08。
模拟观察及任何模拟祖先均排除，即使当前运行在 demo。计划、发现标题、未知结果均不算完成。

投影使用 `MemorySources` 的完整祖先和 `MemoryProjections` 的原生完成证明，继承隐私、
保留期限、OwnerAuthority 原始输入授权、Ledger custody 和来源遗忘语义。窗口为最近
14 天，最多核验 256 个候选；溢出明确显示 `truncated` 并停用底色，以免不完整历史造成
长期结论。普通聊天在 SQL 提名阶段已排除，不会把仍有效的心情来源挤出窗口。

### 日常互动的归因边界

正常聊天的 Pydantic AI 最终输出仍是文本，没有已有的结构化情绪评价可供直接消费。
因此本次扩大确定性原话提取的同时，增加记忆提取阶段的模型判断。

#### 确定性原话提取

每类接受少量明确完整句子，以及”，我们继续聊聊””，想再听听你的看法”两种完整后续分句；
可带句末句号或感叹号。不做关键词或子串命中，否定、假设、引文、混合转折句与不确定表达不采纳。

“这个想法”等指代只绑定同会话最近已 SENT 的私聊回复，要求它的原始输入正是当前事件
之前的上一条主人消息，且该回复在当前事件发生前一小时内已送达。中间出现未回应的其他
话题（含媒体消息）、较新的 SENDING/DELIVERY_UNCERTAIN 回复，或当前输入带引用、富文本、
附件、分享内容或控制指令时，不猜测归因。
一小时限制用于确定新事件的指代对象；已经采纳的事件仍按原有 14 天窗口和半衰期衰减，
不会在一小时后突然清零，也不把迟回复解释为负面情绪。

#### 模型判断（新增）

记忆提取阶段增加 `interaction_signals` 输出，从主人用词识别五类情感表达：

| reason | PAD 增量 | 示例 |
| --- | --- | --- |
| OWNER_AFFECTION | +.05 / +.02 / +.01 | 撒娇、想念、亲昵称呼 |
| OWNER_HURT_BY_REPLY | -.04 / +.03 / -.03 | 因回复受伤或被拒绝感伤害 |
| OWNER_DISTRESS | 0 / +.03 / 0 | 遇到压力麻烦或难过 |
| OWNER_EXPECTATION | 0 / +.025 / 0 | 对陪伴、主动联系、回应或共同约定表达期待或失望 |
| OWNER_PLAYFUL | +.03 / +.02 / 0 | 开玩笑、逗 AI 或轻松玩闹 |

提取规则（`EXTRACT_RULES`，随每次记忆提取请求发送）要求：
- 只从主人的实际用词推断，不从 AI 回复或情景推断
- 排除否定、引号内的转述和纯假设；拿不准不输出
- 愿望、邀约、撒娇式请求或问句也可以表达当下真实的关系期待，不要求出现“期待”一词；
  未来互动尚未发生不等于纯假设。普通查询、计算、提醒等任务请求不产生期待信号
- 长期记忆与互动信号分别判断；同一事件可同时保存关系约定和期待信号
- 别人或别的事让主人难过归 OWNER_DISTRESS，不归 OWNER_HURT_BY_REPLY
- 每条含 event_id、reason（选一种）、quote（逐字引用主人原话 2–200 字）

验证与限制：
- 同一事件只能产生一个 appraisal 信号（与确定性原话提取去重）
- 时间：记录在提交时刻（`created_at`）才算已知，历史回放不提前使用；已知后，衰减、
  14 天窗口和自然日都按主人消息的 `occurred_at` 计算，后台延迟处理不会把旧话当成新刺激
- 每类 reason 每个自然日（按主人时区、消息发生日）最多采纳 2 条，保留最早的两条；
  先做原话、结算、来源链和消费范围校验，无效或当前消费者看不到的信号不占额度；
  原始记录不因投影限额删除，重算时仍按同一规则选择
- OWNER_HURT_BY_REPLY 绑定主人消息前一小时内最近一条已 SENT 的私聊回复或主动消息，
  保存 `target_message_id` 和回复指纹；其间有可能已送达的 SENDING/DELIVERY_UNCERTAIN
  消息时不猜测归因。每次投影复核同一回复仍是唯一目标、指纹未变，回复的原始输入
  也进入来源链，被遗忘时该信号失效
- 记录包含 quote_sha256、来源链和回复指纹，支持遗忘和重放

每次提取写一条不含原文的审计 `mood.appraisals_extracted`（实体为该次 `request_id`）：
`field_present` 区分模型漏掉字段与返回空列表，另记 `returned`、`kept`、按代码计数的
`rejected`（OUTSIDE_BATCH、DUPLICATE_EVENT、NOT_OWNER_TEXT、QUOTE_NOT_FOUND、
NO_REPLY_TARGET）和保留信号的 `reasons` 计数，用于定位"没识别"和"识别了被过滤"。

提取费用结算后，Core 在同一事务内复核来源、校验信号并写入 mood_appraisals。
有合法信号时，mood.appraisals_committed 按提取请求记录实际新增、已存在和功能关闭的数量。
同批普通事实随后进入记忆审核，审核失败仍保留已提交的信号和原费用。
当前可用信号以心情投影的 signals 为准；核对表达使用时，还要检查实际请求中的心情参考和对应来源。
投影仍使用原有的 14 天窗口、256 候选上限和半衰期。

2026-11-03 的 QQ 小样本中，一条早安请求已保存为关系约定，但模型没有输出期待信号，
审计显示无校验拒绝或截断。独立合成库使用相同 DeepSeek Flash 和原生提取/预算链路重测：
原五条输入在修订前后各三轮均符合预期，因此原句漏提并非稳定复现。另一组四条陪伴/联系
期待和六条否定、假设、转述、工具请求对照，在修订后全部正确提取并提交。旧版对照的
原始响应把两条期待归为亲近，其批次另因结构校验失败而未提交；不把这批入库为空计作
十条语义判断失败。该小范围回归用于验证提示词边界，不代表总体识别准确率。

#### 共同原则

这些是对真实互动反馈的小幅表达参考，不是把主人的心情复制成小肥鱼的心情。观点分歧
只产生很小的唤醒度参考，不降低愉悦度或支配感，不推断关系受损。”没想到”只参考新颖
程度，不假定是好消息；明确”眼前一亮”才增加一点愉悦度。好奇只说明当前实际
表达了探索意愿，讨论进展只说明实际反馈了理解进展；均不证明后续阅读、任务或线下行为
已经完成，不产生工具权限或目标成功记录。模型在回复、日记或反思中说自己兴奋不算来源。

每个信号保留 `kind=interaction` 或 `kind=appraisal`、具体原因、原始反馈及回复输入的
完整来源链和回复指纹。授权、来源遗忘、跨日重建、作用域筛选和发送前复核继续走原机制；
控制台展示十类中文来源原因（五类确定性 + 五类模型判断）。有限词句之外的普通闲聊仍可不更新；
这不是通用的聊天情绪识别器。

## 表达与消费边界

- 聊天：Core 把短小参考放在动态 user 数据段，登记 `job_sources` 与独立来源指纹。
  Context Planner 将其作为最低优先级的可裁剪 reference；聊天只携带规则、表达值、
  置信度和评估时间，完整来源留在证明中。见[跨模块选择](p10-provider-evidence-delta.md#2026-10-31跨模块的本地上下文选择)。
- 日记/反思：回顾已结束日，在日末采样；只取本轮已获准来源的子集。生成前、模型边界
  和提交时复核同一证明。生成的感受和假设不回流为心情事件。
- Life：只取本次活动已获准来源，冻结采样时间；执行和送达复核使用这个时刻，避免正常
  衰减导致草稿被误判为来源变更，同时继续按当前时间检查来源有效性。
- 复用 `expression.SERIOUS`，严肃/危险语境不附加滤镜；主人的 Affect 暂停偏好优先。
  数据中的规则要求自然、有限、可不表达；不指定台词，不改事实、理性判断或能力权限。

没有工具执行、消息发送、预算扩张或额外调用入口。清除、暂停和来源变化会使已冻结的
心情证明失效；发送仍走原有的鉴权、租约、投递复核和不确定性处理。

## 查看、暂停与清除

控制台“情绪与偏好”页分别展示主人的交流偏好和“小肥鱼的心情”。新增接口沿用现有
主人 Session、同源检查、CSRF、Idempotency-Key 和隔离写连接：

- `GET /v1/console/mood`：当前两层、表达参考、来源及规则、24/6/1 小时前与当前趋势、
  半衰期、截断和清除边界。趋势只基于当前仍有效的来源重建。
- `POST /v1/console/mood/control`：`action` 为 `pause`、`resume`、`clear` 或 `recompute`。
  暂停只停用心情参考，原始互动/阅读仍照常记录；恢复时从有效来源按实际时间重建。
- 清除向原 ErasureLedger 写入独立 `mood_reset` 记录；空 event/memory 删除范围，单调
  推进时间边界。重试不推进边界，重算不越过边界，旧备份必须重放最新 Ledger。
  清除不删除聊天/日记/记忆，不重置 Affect 或 Interest。

即时值和底色不持久化，因此来源遗忘或到期后，重读即撤销对应贡献，无需第二套清理表。
手札继续由原 Diary/Reflection 来源清理和备份重放负责。
