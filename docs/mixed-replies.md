# 有序混合回复

主人私聊的一轮回复可由模型选择多个独立气泡，例如文字、语音、表情、文字，或文字、完整歌曲、图片。
用户无需使用固定指令。普通文本输出仍沿用原有分段策略；结构化输出的每个文字项是一条气泡。
成功语音不会自动再发一份文字，需要额外文字时由模型显式列出。

## 原生输出与来源

`reply_with_parts(parts)` 是 Pydantic AI 的一次最终输出，不是发送工具或另一次模型请求。
它替代新生成时的单独语音、歌曲最终输出。历史记录中的旧选择和投递回执继续按原义校验。
已经观察并结算、尚未来得及完成的旧最终调用只通过原 SDK 检查点读取；该恢复路径禁止再调用模型，
也不会把旧输出工具重新提供给新的生成。已冻结的 OUTPUT 复用原结果和来源校验。
Core 保存完整的类型化选择，并在同一事务中建立原生 Outbox 组：

| kind | 模型提供 | Core 负责 |
| --- | --- | --- |
| text | 文字 | 隐私脱敏、冻结内容、原生发送 |
| voice | 要朗读的自然语言 | 原节点合成、结果绑定、语音发送或发送前文字回退 |
| meme | 本轮候选的 candidate_id | 原候选审核、来源、概率、冷却、严重语境与素材核对 |
| generated_image | 本轮成功工具结果的 image_id | 核对原工具、原事件、有效期、文件与原生素材读取 |
| singing | 本轮 READY 的 request_id、内部介绍 | 重新校验原歌曲来源，完整展开连续音频分段 |

最多 32 个逻辑项、64 个展开气泡，总文字不超过原有 20,000 字硬边界，并继续受主人授权的
`max_reply_chars`、分段数量、发送次数和各能力额度约束。每种图片和歌曲最多一个来源。
图片、音频来源不能由模型以任意网址、文件路径或自造任务替代。表情因原策略不可用时可以省略，
其余已选的文字和语音仍保持顺序。

## 逐条冻结与独立 Bridge

新混合组使用原分段队列的内容绑定 v3。`content.reply_part` 包含 `kind` 与逻辑 `source_index`；
歌曲额外保存原 `request_id` 与歌曲自己的 `singing_segment_index`。
每条完整内容参与 `part_sha256s` 和组清单摘要，Bridge 独立校验类型、来源引用形状及摘要。
一段歌曲在整轮中的位置和它在歌曲内部的位置分别绑定，前后增加文字不能更换音频分段。
v1 文字组、v2 文字加末尾图片组的历史语义及摘要不变。Core 与 Bridge 须一起发布以启用新输出。

每个气泡仍使用原 message_id、delivery_key、AuthorityRef、原输入、回复版本、模型结算、
来源快照、租约和发送凭据；模型不获得消息发送或素材访问权限。没有第二个队列、发送器或模型循环。

只有前面的气泡获得原生成功回执，后续气泡才可领取。主人新消息、撤回、STOP、来源失效、
遗忘和隐私期限继续阻断未发送部分。QQ 结果为 UNKNOWN 时保留原责任并停止后续发送，不补发或重放。
普通语音在发送尝试前失败或超过原等待期限时，只把对应气泡回退为文字，保留同一 Outbox 身份。
成功语音、已送达文字、图片和歌曲不因恢复而重复发送。

语音节点、v1 音色、模型、预算、权限、付费合同及原 UNKNOWN 记录无需因此改变。
完整歌曲生成仍走原 `sing_song` 延迟工具和原节点，长歌只在原分段边界拆开。

  仍适用；没有运行 DSH 或复制其执行循环。

  设备音频和 OneBot 传输使用模拟端点。覆盖顺序、分段完整性、失败回退、来源替换、发送不确定性、
  恢复以及既有撤回/中断/隐私回归。真实 QQ 实收按部署后的新主人消息另行验收。
