# 费用记录与运行边界

2026-11-08 主人要求先取消资金预算的运行硬边界，并将费用 UNKNOWN 降为提示，
用于验证回答耗时。随后确认拆分授权校验与费用对账的边界。本规则替代历史文档中
因金额超额或单纯费用 UNKNOWN 拒绝新工作的描述。

当前配置、委托调整和控制台已移除单次、逻辑请求、窗口、日、月、累计账户及云服务的
金额上限、资金预算分配和超额阻断。历史批准快照与账本保留原始字节和金额，供审计与核对。
累计资源策略使用 v2；原 v1 策略仅按原义读取、验证和回放历史证据。
功能开关、用途授权和来源范围独立控制是否启用。

模型调用依然先登记原请求 ID 和预留，再记录实际 HTTP 派发和结算。真实费用和 usage 可知时
照实记录；缺少 usage 或请求结果未知时保留原 UNKNOWN 与金额下界，不改写成零费用或 SETTLED。
费用 UNKNOWN 不继续占用模型并发槽，也不使其他独立请求停机。运维快照通过
`warnings` 的 `MODEL_COST_UNKNOWN` 提示，并保留原未知费用计数和估算标记。

已收到并持久化的真实模型回复，即使费用 UNKNOWN，也可继续原对话及投递。没有收到回复的
超时请求不能生成替代回复，原不确定尝试不能自动重放。新独立请求可以继续。

以下边界继续生效：主人身份与 ACTIVE 授权、用途和签名、STOP、原任务租约与幂等、
来源及删除重放、实际模型并发、输入输出与上下文大小、调用次数和调度频率，以及
发送不确定的原核对与防重发规则。费用 UNKNOWN 与 `DELIVERY_UNCERTAIN` 含义不同。

授权读取复用原 PostgreSQL 账本锁、原独立日志的哈希链解码、授权修订投影校验和窗口生命周期
校验；授权修订、生命周期和删除投影在同一原生快照中批量读取，继续检查最新 ErasureLedger。
授权检查不再汇总费用或对账模型费用投影。
图片分析、图片生成、语音媒体和执行器模型代理同样不因金额额度拒绝运行；
字节、图片数量、调用次数、冷却时间和权限检查仍有效。
请求登记、结算、账本追加和显式运维对账仍使用完整费用验证器；账本损坏和证据不一致仍会报错。
原账本、备份原件和历史费用均保持原义。非模型媒体端点的可选
`estimated_request_micro_usd` 是缺少服务商账单时的估算记录，不能作为运行上限。
执行器代理从原 JSON 响应或 SSE 最终 usage 记录实际 Token，按配置费率计算费用，
不把预留估算额当成已付费用。原结果可用但部分调用缺少 usage 时，结果继续处理，
费用保持 UNKNOWN；已知费用、调用数和 Token 通过原工具完成审计记录持久保存。

升级时从部署 TOML 移除旧金额控制字段，并按现有配置版本流程保存清理后的新版本。
旧配置版本、授权快照和账本原件保留，历史版本恢复仍须满足当前配置结构并重新授权。

测速使用真实 Core HTTP 入口与独立 Worker，供应商 transport 为合成响应。原测试的 1.5 秒
入队时限和其他进程时限保持不变。测速诊断与正常验收分别记录，诊断通过不能替代验收。
