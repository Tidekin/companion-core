# 召回鲜明度与心情顺序

主人常提起的事更容易被想起，她当下的心情也会影响先想起哪些。两者都只调整已经合格的
候选记忆的先后，不决定哪些记忆能被召回，不改变记忆正文，也不能作为事实来源。实现见
`companion/memory_salience.py`，排序入口是 `Memory._fused_order`。

## 什么算“提到”

- 只算主人在私聊里发来的消息：这条消息和某条被放进回复上下文的记忆，字面上至少共享两个
  检索词（与关键词召回同一套切词）。
- 她自己调用 `memory_recall`、复述、日记、反思都不算；排序加成本身也不会产生新的提及，
  所以鲜明度不会自我循环。
- 每条（记忆，主人消息）只记一次，记在 `memory_mentions`（`pg0012_memory_mentions`），
  时间取主人消息到达的时刻。

## 鲜明度

每次提及按 30 天半衰期淡化，只看最近 180 天。同一天内的重复提及逐次减半，和心情的
重复规则一致；总强度最多为 4。加成为 `0.0008 × log2(1 + 强度) / log2(5)`。

## 心情顺序

一条记忆的“情绪色彩”取自它来源消息上的模型判断心情信号（`mood_appraisals`），按各原因
的 PAD 增量相加。与当前心情表达值方向一致（余弦为正）时加分，最多 `0.0005`，心情较弱时
按强度缩小。严肃或敏感话题不取心情，与心情参考的过滤规则相同。

## 边界

- 互惠排名融合中，靠前两名的分差约 0.00026；两项加成合计不到六个名次，原文精确命中的
  记忆仍然排在最前。启用重排模型或旧路径的模型相关性复核时，最终顺序仍以它们为准。
- 回复的召回追踪在 `selected.<memory_id>.salience` 记录 `bonus`、`vividness` 和 `mood`。
  控制台“召回测试”不带这两项，显示的是基础排序。
- 删除主人消息时，该消息产生的提及随来源清除；遗忘或删除记忆时，它的全部提及一起清除；
  旧备份恢复时随遗忘日志重放。
